# Stage 1.4 — AXON: сайт, полный Mini App и бот

Развитие опубликованного Stage 1.3 (main 4acccb010eb23ad88a937abe703cb458e825c21e), без нового приложения, ORM, UI-фреймворка или production-проекта. Код Stage 1.4 готовится в отдельной ветке stage-1.4-axon-ui; публикация Render и изменение меню существующего бота требуют согласованного выпуска.

## Дизайн и структура

AXON — чёрно-белые токены, графитовый фон, светлая тема, полупрозрачные панели, тонкие границы и крупная типографика. Геометрический знак и orbital hero выполнены SVG/CSS; нет тяжёлого изображения, внешнего шрифта или новой библиотеки UI. Светлая тема сохраняется по прежнему ключу shared-vps-theme; новая сессия браузера по умолчанию использует тёмную. В Telegram тема синхронизируется с клиентом.

Главная гостя объясняет продукт, три формата работы и демо-границу. Авторизованная главная показывает подписку, оставшиеся дни, быстрые действия и последние заказы. Каталог читает действующие тарифы; при активной подписке на этот тариф предлагает продление, используя прежний renewalId. Ничего не списывает без явного подтверждения демонстрационной операции.

Общие маршруты сайта и Mini App:

| Маршрут | Возможности |
|---|---|
| / | Гостевой hero или личный dashboard |
| /catalog | Тарифы, демо-покупка/продление |
| /subscriptions | Статус, срок, VPS, управление подпиской |
| /renew | Подписки, доступные для продления |
| /connect | Демо-идентификатор, копирование, инструкция |
| /orders | История заказов, фильтры, поиск, cursor-пагинация |
| /history | История подписок, фильтры и cursor-пагинация |
| /support | Обращение и постраничная история поддержки |
| /notifications | Общие opt-in настройки бота и сайта |
| /profile | Проверенный аккаунт, настройки, выход, полезные разделы |
| /instructions | Короткий путь по сайту и Telegram |
| /login | Прежний вход через подтверждение, ссылку или код |
| /admin | ADMIN-диагностика и пагинация Stage 1.3, настройки в компактном раскрываемом блоке |

В мобильном интерфейсе пять нижних вкладок: Главная, Каталог, Подписка, История, Профиль. В профиле находятся поддержка, инструкции, уведомления и ADMIN-ссылка, если сервер вернул соответствующую роль. Десктоп сохраняет верхнюю навигацию. Скрытие ADMIN-ссылки не является защитой: прежние серверные проверки роли остаются обязательными.

## Telegram WebApp

mini-app.ts изолирует необязательные возможности SDK: ready/expand, BackButton, SettingsButton, themeChanged, viewportChanged, safe areas и haptics. Native Back возвращает на dashboard, Settings открывает уведомления. Неиспользуемые/устаревшие возможности не должны ломать браузер. MainButton намеренно не дублирует покупку: постоянная нижняя навигация и подтверждаемый CTA остаются единым способом действия.

Используется только подписанный initData и прежний серверный валидатор. initDataUnsafe не используется как identity. Даже при существующей cookie Mini App обращается к серверному входу: несовпадение аккаунта скрывает личные экраны и предлагает явную смену аккаунта. Только известный LOGIN_REPLAY при действующей проверенной сессии допускает её повторное использование; сервер проверяет подпись и совпадение identity до replay-check. Backend auth.ts не переписывается и проверки не ослабляются.

Одноразовый login fragment удаляется прежним takeLoginLink до загрузки стороннего SDK. После инициализации Telegram launch-параметры убираются из видимого route/history; initData не сохраняется в DOM, localStorage, логи или URL запросов. Тема — единственная обычная локальная настройка; прежний sessionStorage восстановления pending bot login сохранён. Старый Static Site по-прежнему перенаправляет на канонический API/site origin.

Без SDK или вне Telegram остаётся полный обычный сайт с прежним входом. Публичная главная и каталог могут открыться во время загрузки необязательного SDK. Подписанные данные проверяются сервером, а не имитируются для обхода входа.

Справочник интеграции: [официальная документация Telegram Mini Apps](https://core.telegram.org/bots/webapps).

## Бот

Сохранены шесть основных быстрых действий и обе кнопки входа. Добавлена reply-кнопка «Открыть приложение» и команда /app, выдающие inline web_app-кнопку корневого Mini App. Inline-меню собирает действия парами, содержит вход, код и уведомления. «Подключиться» открывает контекстный /connect и сохраняет инструкцию в самом чате. Формат сообщений остаётся безопасным plain text; статусы переведены на русский, ошибки предлагают понятный путь назад.

При будущем запуске опубликованной версии bootstrap сначала проверит username существующего vpnaxon_bot и принадлежность webhook. Затем сохранит прежнюю регистрацию без drop_pending_updates и задаст default chat menu button AXON с web_app URL существующего сайта. Чужой webhook не заменяется. Никакой новый бот не создаётся. До выпуска этот Bot API вызов проверяется только transport-имитацией.

Существующий durable inbox, lease, retries, response scrubbing и непостоянные ответы с кодами/ссылками сохраняются. Кнопки покупки и продления вызывают тот же SubscriptionEngine с прежними operation keys. Задачи, уведомления, workers и бизнес-ограничения не заменяются.

## Доступность и производительность

Метки полей, aria-current для навигации, live loading/status, keyboard focus, skip-link, native dialog с Escape и блокировкой закрытия во время отправки. Основные кнопки имеют не менее 44 px по высоте. Длинные ID переносятся; большие административные таблицы прокручиваются внутри контейнера. reduced-motion отключает анимации, reduced-transparency убирает blur, при отсутствии backdrop-filter используются непрозрачные поверхности. Новый раздел прокручивается к началу; cursor-пагинация остаётся локальным обновлением выбранного списка. Устаревший ответ прошлого маршрута отсеивается generation guard.

Никаких метрик fake uptime, действующих VPN-ключей, реальных платежей или аренды VPS. Все суммы и статусы берутся из действующих API, демо-граница видна и на главной, и перед подтверждением, и в подключении.

## Данные, конфигурация и выпуск

Новая DB migration и новые env не нужны. Prisma schema и все четыре миграции Stage 1.3 сохраняются. Runtime-зависимости и pnpm-lock не изменяются. Дополнительный Playwright устанавливается только в одноразовом GitHub runner для UI-проверок, версия закреплена в отдельном workflow.

До выпуска: зелёные Verify foundation и AXON browser checks, просмотр diff/screenshots и разрешение владельца. Затем временный Auto-Deploy Off → merge проверенного PR → Manual Deploy точного SHA → health/ready/auth config stage 1.4 → настоящие bot login / inline Mini App / menu button / покупки / продление / уведомления → Auto-Deploy After CI Checks Pass. Production-миграцию повторять для этого этапа не требуется. Три посторонних suspended Render-сервиса для платформы не нужны и не возобновляются.

Источники проверяемого результата и оставшиеся ограничения — [verification-stage1.4.md](verification-stage1.4.md). Новые скриншоты из облачного теста показывают настоящий собранный frontend с явно тестовыми данными; это не доказательство входа в настоящий Telegram или публикации Stage 1.4 на Render.
