# Контролируемый выпуск Stage 1.6 (пока не выполнен)
Нужны отдельное разрешение владельца на PR/commit и зелёные проверки. Не объединять и не публиковать автоматически.

1. Перепроверить текущий main, head PR, diff, отсутствие конфликтов и все проверки последнего SHA. При изменении main обновить ветку и повторить CI.
2. В существующем shared-vps-api временно отключить Auto-Deploy, зафиксировать текущий Live SHA и read-only агрегаты пользователей/заказов/подписок/обращений, тарифы и capacity settings.
3. Merge согласованного PR → дождаться успешного CI нового main → записать merge SHA и проверить совпадение tree.
4. Stage 1.6 не содержит Prisma-миграций и новых env. Не запускать reset/db push и не мигрировать production «на всякий случай». Если diff изменился и появилась миграция, остановиться до отдельной проверки и согласования.
5. Manual Deploy точного проверенного SHA на существующем Render после необходимых проверок. Не менять DATABASE_URL, секреты, тариф или другие сервисы.
6. Проверить stage 1.6 / version 0.6.0 / demo, ready, auth/config.publicWebMode=landing, планы/инструкции/API/JS/CSS. Старые публичные UI-маршруты ведут к витрине, webhook продолжает проверять секрет, admin и личные API без сессии возвращают отказ.
7. Проверить журналы, heartbeat и очередь. Реальная приёмка владельцем: /start удаляет старую клавиатуру и показывает пять inline-строк; каталог и preview не создают заказ; отдельное подтверждение создаёт демо-подписку один раз; продление/история/поддержка/уведомления работают. /app открывает все разделы без лишнего входа. Проверить браузерный ADMIN login отдельно и старые кнопки.
8. После успешных проверок восстановить After CI Checks Pass и зафиксировать точный Live SHA. Эмуляция SDK не заменяет настоящие Android/iOS/Desktop Telegram. Если владелец планирует самостоятельную приёмку после публикации, отдельно перечислить её незавершённые сценарии.

При критической ошибке остановить выпуск. Предпочитать исправляющий выпуск. Откат Stage 1.5 не требует удаления данных/схемы, но не является бесшовным для новых n:/o:/checkout: callback и продолжений Telegram inbox: сначала согласовать ограничение обработки и сохранение очереди, не удалять updates/jobs. Не переключать production на тестовую базу. Восстановление данных — отдельное решение по backup-recovery.md.

PUBLIC_WEB_MODE=full — будущее согласованное возвращение пользовательской веб-версии, а не автоматический аварийный обход Telegram. UI-флаг никогда не заменяет backend auth/RBAC.
