# База Stage 1.2

Применяются **обе миграции по порядку**:

1. `20261015000000_foundation` — исходная, побайтно сохранена.
2. `20261016000000_unified` — только добавления.

Все 11 исходных таблиц, внешние ключи RESTRICT, проверки стоимости/дат,
триггеры вместимости и `subscriptions_one_live_per_slot` остаются на месте.
История не удаляется. Не применяйте db push, migrate reset или ручное удаление
миграций в облаке.

В orders добавлены operation_key (unique nullable для старых записей), renewal_id
(FK к subscriptions RESTRICT), period_days, attempts и last_error. Старые заказы
получают period_days=30; их прежние подписки и статусы не меняются.

Добавлены sessions (хэш cookie, пользователь/nonce, срок), auth_replays (одноразовое
использование подписанного входа), support_tickets (номер, автор, текст, статус,
необязательный уникальный operation_key), bot_states (ожидание ввода поддержки),
telegram_updates (update_id PK, inbox, сохранённый ответ, lease updated_at, попытки).
Секрет бота, webhook-секрет и cookie в открытом виде в БД не сохраняются.
Telegram initData/JWT не записываются: replay-таблица содержит только хэш.
Telegram inbox содержит сообщения пользователей; срок хранения/очистку следует
согласовать перед публичной эксплуатацией. Автоочистка истории в этот этап не входит.

Денежные величины — целые копейки. Условная выручка — сумма SUCCEEDED платежей,
возвраты исключены. Расходы — первоначальная стоимость VPS + журнал продлений.
Это не бухгалтерский расчёт. Возврат исходной покупки отменяет её подписку;
возврат активного продления уменьшает срок на оплаченный период, отменяя доступ,
если оставшийся срок исчерпан. История заказов/платежей остаётся.

Seed повторяемый: существующие цены/настройки не перезаписывает. Ограничения
новых VPS изменяются только для последующих выделений. В админке максимум 3 места.
