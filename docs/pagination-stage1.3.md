# Пагинация Stage 1.3

`GET /api/v1/admin/lists/:resource`: users, orders, subscriptions, servers, tickets, events, jobs. Только ADMIN; обычный пользователь не может менять scope параметрами.

`GET /api/v1/account/lists/:resource`: orders, subscriptions, tickets. Сервер жёстко добавляет userId из сессии. Параметр userId не разрешён. Курсор связан с ресурсом, поиском, статусом, сортировкой и этим user ID; чужой/неподходящий курсор отклоняется.

| Параметр | Значение |
|---|---|
| limit | 1–50, по умолчанию 20 |
| cursor | opaque nextCursor предыдущего ответа, максимум 1024 символа |
| search | до 80 символов; UUID, Telegram ID для users, текст/номер tickets, VPS ID, action для events, key/kind для jobs |
| status | только разрешённые состояния выбранного ресурса |
| sort | newest или oldest; стабильная пара createdAt + UUID |
| includeTotal | false по умолчанию; отдельный count только по явному запросу |

Ответ: `{ items, nextCursor, limit, total? }`. Получается limit+1 записей, следующие страницы используют keyset, не OFFSET. Добавлены индексы created_at/id и user_id/created_at/id. При параллельных вставках существующие записи не повторяются между страницами с одинаковыми timestamp; это не snapshot-транзакция всей сессии просмотра. Для нового поиска/состояния/порядка нужно начинать с первой страницы.

Выбор полей и Prisma delegate задаётся фиксированным серверным mapping. SQL/имена полей из клиента не принимаются. Job payload, сессии и коды входа в списках отсутствуют. Вложенные списки ограничены. Админка показывает 20 строк и предоставляет «Назад»/«Далее»; история курсоров находится только в текущем представлении.

Прежние пользовательские array endpoints сохранены для совместимости и ограничены 100 записями. Новые account endpoints позволяют клиентам получать полную историю страницами. Telegram использует ограниченное чтение для текущей подписки; его основные действия сохраняют прежний engine.
