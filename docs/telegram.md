# Один постоянный Telegram-бот

Используйте существующего бота и его TELEGRAM_BOT_TOKEN. Программное обновление
не создаёт нового бота. В Stage 1.2 бот работает через `/api/v1/telegram/webhook`
в том же Fastify Web Service. Отдельные polling/worker сервисы не нужны.

`/start`: 🛒 Купить подписку, 👤 Моя подписка, 🔌 Подключиться,
🔄 Продлить подписку, 📖 Инструкции, 💬 Поддержка.
Основные действия выполняются в чате. Mini App предлагается дополнительно.
Поддержка хранит ожидание текста и номер обращения в общей базе. В группах
персональные операции не обрабатываются. Сведения о подписке читаются через
общий SubscriptionEngine из PostgreSQL, а не из памяти Telegram-процесса.

Покупка создаёт заказ и показывает отдельную кнопку подтверждения. Callback
содержит orderId; backend проверяет владельца. Повторная кнопка не повторяет
платёж/активацию. Неподтверждённая inline-кнопка старше 30 минут отменяется
и предлагает начать заново. `/start` прекращает режим ввода обращения.

Webhook принимает только запросы с правильным X-Telegram-Bot-Api-Secret-Token;
секрет сравнивается timing-safe. Update сохраняется перед HTTP 200. update_id
уникален. Ответ и бизнес-операция восстанавливаются после перезапуска; текст
callback-ответа редактируется в исходном сообщении. Inbox использует lease
2 минуты и до 5 попыток. После пяти ошибок доставка требует диагностики в базе;
автоматического бесконечного цикла нет.

**Граница гарантии:** Bot API sendMessage не имеет клиентского ключа идемпотентности.
При потере сетевого ответа после отправки, но до записи DONE, текстовое сообщение
может повториться. Покупки и продления при этом не дублируются. Обещания exactly-once
доставки нет. Для callback используется editMessageText и обработка «not modified».

Регистрация: защищённая ADMIN-кнопка «Зарегистрировать webhook» отправляет
setWebhook с PUBLIC_ORIGIN, secret_token и drop_pending_updates=false. Затем
«Проверить webhook» показывает URL, количество ожидающих updates и время ошибки
без токена и сырого описания ошибки. Token никогда не попадает в URL браузера.

Сон Render Free останавливает обработчик и интервалы. Telegram повторяет
неуспешную доставку, но cold start может задержать ответ; длительные остановки
и срок хранения updates Telegram не позволяют гарантировать доставку 24/7.
Для будущего постоянного размещения нужен always-on web + durable worker/queue,
без искусственных keep-alive.

Источники: [Bot API webhook](https://core.telegram.org/bots/api#setwebhook),
[ограничения Render Free](https://render.com/docs/free). Проверено 16.10.2026.
