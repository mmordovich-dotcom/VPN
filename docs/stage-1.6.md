## Навигация и доставка бота
Новые n: callbacks редактируют навигационное сообщение. Кнопки перехода из подтверждений/переписки используют o: и отправляют новое меню, сохраняя важное сообщение. Старые callbacks открывают новые сообщения и сохраняют владельца/идемпотентность старых confirm/cancel. Подтверждение старше 30 минут отменяет неоплаченный заказ штатным механизмом.

ReplyKeyboardRemove отправляется отдельным коротким служебным сообщением: Telegram не позволяет объединить его с InlineKeyboardMarkup. После подтверждённой доставки этого шага сохраняется continuation в существующем Telegram inbox; безопасный retry основного меню не повторяет служебное сообщение. Старые сохранённые responses с Reply Keyboard также преобразуются. Неопределённая доставка остаётся в quarantine, а не рассылается повторно.

answerCallbackQuery вызывается сразу после сохранения update, до очереди; drain повторяет ACK как fallback. Просроченный ACK не повторяет бизнес-операцию. Message-is-not-modified считается успехом. При подтверждённой ошибке недоступного редактирования отправляется новое сообщение; неопределённая сетевая доставка не считается успехом. API-rejection необязательного style приводит к единственному повтору без style. Внешний вид старых клиентов определяется Telegram.

## Режим сайта и безопасность
Внутренняя настройка PUBLIC_WEB_MODE в packages/shared/src/interface-policy.ts сейчас landing; full позволяет будущим согласованным выпуском вернуть прежний веб-интерфейс. Исходники не удалены, новых env нет.

Telegram launch hints только загружают SDK. Для пользовательского Mini App интерфейса нужны активный WebApp и miniApp=true из серверной сессии. Auth помечает проверенную initData-сессию существующим nonce=miniapp:v1, не возвращая nonce клиенту. Это не JWT challenge: JWT-ветка явно отвергает этот marker. Обычные Bot Login/код/ссылка-сессии не получают marker. Миграция не нужна. Ошибка подписи и смена аккаунта не открывают данные старого аккаунта; known replay повторно использует только уже помеченную действующую сессию.

Это граница представления, не замена авторизации API. Каждая операция по-прежнему проверяет cookie, статус пользователя, владельца, роль и CSRF. Поддельный query flag/SDK не выдаёт сессию или ADMIN. API, assets, health, webhook не перенаправляются в Telegram.

Браузерная админка доступна по /#/admin с обычным безопасным Bot Login. USER получает отказ; ссылки на admin support thread разрешены в оболочке только для подтверждённой роли ADMIN, и backend независимо повторяет проверку.
